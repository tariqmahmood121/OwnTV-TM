# QA3 specification reconciliation

The final QA3 specification governs this audit. The branch retains the Central QA2 integration, the subsequent persistent-cache fixes, and the signed QA3 implementation. The release workflow uses version name `1.0.83-qa3` and code `100085`.

| Specification | Implementation and automated evidence | Remaining verification |
| --- | --- | --- |
| 1, 14–16. Baseline, testing, delivery and feature freeze | QA3 builds on the current branch. The signed workflow runs the translation inventory, XML prechecks and Standard Debug unit suite, builds StandardRelease and verifies its signature. The changelog and separate PHP package document the release. | End-to-end cases below remain open. |
| 2. Catalogue playback | Direct resolution uses verified TMDB external IDs when the Plesk update is deployed. Cinemeta fallback requires one exact title and full-date match. Add-on prefix matching, request deduplication, legacy resume identities and source aliases share the playback path. Unit fixtures cover verified and ambiguous matches and add-on compatibility. | Play Central cards with the installed add-ons on an authenticated test account. Check continuation from older favourites and resume records on a device. |
| 3. Persistent catalogue caching | The application repository stores catalogue and manifest responses across launches, shows stale content while refreshing, deduplicates requests, limits storage and isolates provider and profile data. Manual refresh and local poster caching are wired. The audit added a test for retaining the Central fallback policy across retry cooldown. | Measure cold and warm catalogue load times on phone and TV. |
| 4. Navigation state | The shell retains the originating browser during MovioXP playback. Stable, page-scoped poster keys identify the original position independently of item order. Show and episode selection and zoom are retained. The new unit fixture checks grid scoping and reordered poster lookup. | Actual Back, D-pad focus, scroll and episode restoration need device playback tests. |
| 5–7. Discover, Library and Home | Discover and Library share the responsive vertical grid. Discover provides the ordered sidebar, category and title search, local sorting, supported pagination and independent zoom. Library adds shared Favourites, History, Continue Watching and Watchlist. Legacy Continue Watching entries become visible in History until a dedicated history collection is saved. Home keeps its configurable rows and zoom. | Cross-device collection checks, foldable and tablet layouts, TV sidebar focus and pinch-to-zoom remain open. |
| 8–10. Ratings, poster badges and sorting | IMDb is preferred when present and TMDB remains available as a fallback. Details name the source. Poster badges retain the star, numeric rating, release year and progress. Profile settings cover visibility and seven sort modes, including category defaults. The audit wired explicit sorting into Search while preserving provider relevance by default. | Check badge visibility and ordering across layouts and devices. |
| 11. Central | The Plesk package extends the documented authenticated contract, preserves shared caching and provider policy, and adds verified identity lookup and bounded pagination. PHP lint and 14 isolated checks passed. Android sync uses the existing Central record types and per-profile settings. | Approved Plesk deployment and authenticated resolver, pagination and multi-device sync checks are outstanding. |
| 12–13. Phone, TV and diagnostics | Responsive grid and sidebar layouts, purple focus styles and opt-in diagnostic logging are implemented. Diagnostics record cache activity, response status, metadata fallback, source requests and navigation without request credentials. | Physical phone and TV input, including foldable sizing, require device testing. |
